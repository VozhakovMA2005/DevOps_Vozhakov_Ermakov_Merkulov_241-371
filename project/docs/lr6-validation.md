# Проверка подготовленного комплекта ЛР6

Дата: 17 ноября 2026. Исходный main: 7f52e41b515e742102ccbaa33d6ae70da173f44f.
Проверялось локально в Windows, Python 3.12 из рабочего runtime.

## Выполнено

- Новые проверки доставки: 18 unittest, все прошли. Проверены отказ registry,
  неверные теги/метки, отсутствующая настройка, несовместимая схема, health/scenario
  failure, возврат, recovery-failed, первый неудачный выпуск, идемпотентность,
  непустой каталог/карточка и структура Compose.
- Модульные тесты приложения: 176 passed. В том числе две новые проверки
  совпадения Alembic-ревизии и две проверки зависимости CD от публикации.
- Ruff 0.8.6: lint и проверка форматирования всего project.
- Mypy 1.14.1: app, scripts, deploy/cd/cd.py; проверка с --platform linux,
  так как целевой сервер Linux, а исходный image_scan.py использует os.getuid/getgid.
- Bandit 1.8.0: app, scripts и контроллер CD; ошибок не обнаружено.
  Подавления отдельных ложных срабатываний имеют локальные объяснения.
- ci-sync: 14 обязательных стадий совпадают; CD зависит от publish.
- waiver-check: нет необоснованных подавлений; порог покрытия не снижен.
- secret-scan: проверено 200 файлов, секретов и запрещенных файлов не найдено.
- CODEOWNERS: 100 критических файлов покрыты правилами с минимум двумя владельцами.
- acceptance-guard против origin/main: ослаблений нет, число учитываемых тестов 243 → 247.
  Вывод о критических файлах означает необходимость ревью при реальном PR.
- Python AST и YAML workflows разобраны; зависимости, environment, ограничение main
  и общая concurrency-группа проверены.
- Сгенерированный compose.json проверен установленной Docker Compose командой
  config --quiet. Эта проверка не требует запущенного Docker daemon.
- Bash -n для remote.sh и drills.sh.
- Пять HTML открыты локально в Edge headless; внешние ресурсы отсутствуют,
  переполнения документа на desktop нет; основной гайд проверен при ширине 390 px.
- Снимки задач и changes сверены по хэшам; вложенные ZIP проверены на целостность.

Инструменты ruff/mypy/bandit и прямые зависимости взяты в версиях из requirements-dev.txt.
Локальная установка транзитивных зависимостей могла отличаться от lock-файлов;
CI и Docker должны использовать сохраненные исходные lock-файлы с хэшами.

## Не выполнялось в этой сессии

Docker daemon на машине не запущен. Не запускались контейнеры, PostgreSQL,
интеграционные тесты, миграционные учения, полные make verify/make ci,
container-check в работающем окружении и сканирование собранного образа.
Порог покрытия 70%/80% сохранен, но новый полный отчет о покрытии не получен.

Нет учетных данных целевого staging и доступа к управлению GitHub этого проекта.
Не создавались реальные Issues/PR, одобрения, коммиты в удаленном main, теги,
опубликованные образы или удаленные релизы. Автоматический деплой, успешный rollback
и отрицательные опыты на живой VM следует выполнить по cd.md и cd-defense.md.
Шаблон evidence-template.md предназначен для их фактических результатов.

Обнаруженные ограничения не замаскированы зелеными статусами или вымышленными логами.
